# Fast refresh query and throttle evidence

The deployed client uses a persisted Marketplace search operation and separate detail and gallery operations. Search parsing retains supplied title, price, location, thumbnail, seller, mileage, structured vehicle attributes, subtitles, availability, posted time, and other card metadata. Cached detail fields survive card observations. The retained 15-card inspection has 44 listing field paths and no transmission or title-status paths. The structural inventory is in `fast-search-initial-field-inventory.json`, without example listing values. This does not prove richer initial search is impossible.

A primary reverse-engineering report describes newer search bootstrap, content, and pagination operations captured on April 23, 2026. Its documented search response still contains card fields, with description in the separate detail operation. Its document IDs and Relay variables are session-sensitive evidence, not verified replacements for the current deployment. No richer vehicle-search operation or Marketplace detail batching was verified in this work. See https://raw.githubusercontent.com/minzique/fb-cli/main/docs/API.md and https://raw.githubusercontent.com/jdcodes1/facebook-marketplace-mcp/master/src/facebook/queries.ts, inspected October 9, 2026.

The earlier investigation retained an HTTP 200 GraphQL response with code 1675004, Rate limit exceeded, on Render after a cooldown. A later October 4 request also throttled while a local request returned cards. This demonstrates actual upstream throttling and differing execution contexts. It does not establish a rate threshold. Evidence is in the root checkout's artifacts/facebook-render-logged-out-throttle-confirmed.json and docs/implementation/facebook-http-failure-diagnosis.md. These files belong to separately dirty root work and are not included in this feature commit.

Keep the application policy of three request starts per minute and existing cooldowns. Remove automatic per-card details and optional gallery fallback from the refresh path instead. The earlier 20.902 and 22.002 second detail observations included a second gallery request and pacing. They are individual observations, not a before-and-after benchmark.

Acceptance reports measure end-to-end production saved-search POSTs, forced detail POSTs with fetchPhotos false, cached conditional POSTs, and browser click-to-saved-title display. Each timing must accompany a successful output and persistence assertion. Two distinct searches are acceptance samples, not a speedup benchmark or evidence that Facebook will never throttle.
